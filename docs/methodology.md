# 事实核验方法学

本文档说明 `geo-facts` 的事实管理、文本与数值归一、陈述拆解、双向判定、判定校准与合成标注集基准的设计规则。所有规则均以当前源码的实际行为为准。

> **重要声明**
>
> - 本工具只给出**预检结论**与建议，不构成独立第三方验证（`047 §15.2`）。
> - **合成标注集上的结果只能说明实现符合预期，不代表真实业务准确率。**
> - **自由文本陈述在没有真实人工金标集之前标为“未验证”**，规则判定器一律返回 `unverifiable`。

---

## 1. 事实库：三区分治、来源等级、时效与冲突

### 1.1 三区分治

事实库（`facts.jsonl`）按 `zone` 字段划分为三个分区，三区分治、互不混用：

| 分区（`zone`） | 含义 | 能否作为判定依据 |
|---|---|---|
| `fact`（事实区） | 可核验的客观参数、价格、时间、政策等 | 满足状态、时效、证据与无冲突条件时可以 |
| `opinion`（观点区） | 媒体试驾评价、市场定位等主观观点 | 不能 |
| `marketing`（营销表达区） | 广告语、品牌主张、推广口号等 | 不能 |

- 核心事实（`is_core: true`）必须位于事实区，且必须绑定完整证据（`026 §6.2`）：`evidence_id`、`source_name`、`source_ref`、`collected_at`、`last_verified_at`（不得早于 `collected_at`）、`reviewer`。
- 实体文件（`entities.jsonl`）、事实文件（`facts.jsonl`）与审计日志（`audit.jsonl`）均**只追加、不覆盖、不静默删除**（`047 §14`）。同一 `fact_id` 更新内容时自动追加递增的 `version`，旧版本全部保留。

### 1.2 来源等级与内容用途独立

- **来源等级**（`source_tier`：A～D）与**内容用途**（`content_use`：`specification` / `pricing` / `policy` / `test_result` / `review` / `promotion` / `other`）是两个独立字段，互不推导。
- 另有可选字段 `source_type`（如“企业官网”“评测媒体”），仅作文字记录，不影响来源等级。
- 导入事实区记录时若 `source_tier` 留空：
  - 当证据链接 `source_ref` 属于该实体或其上级品牌登记的自有域名（`owned_domains`）时，按 026 默认补为 **C 级**，并在 `ext.source_tier_defaulted = true` 及检查提示中标注，提醒人工复核；
  - 其他来源若留空则报错拒绝写入（观点区与营销区允许 `source_tier` 为空）。

### 1.3 `--as-of` 与时效规则

按查询日 `as_of`（`YYYY-MM-DD`）取当时有效的事实版本：

- **有效期内**：满足 `valid_from <= as_of`，且 `valid_until` 为空或 `as_of <= valid_until`（两端均含当天）。
- **版本选择**：同一 `fact_id` 在查询日处于有效期内的版本不止一个时，取 `version` 最大的那个；被更高版本取代的同日旧版本记为 `superseded`，失效日早于查询日的旧版本记为 `expired`。
- **可作为确定依据的条件**：一条事实在查询日能作为确定依据，必须同时满足：
  1. 处于有效期内（非 `expired`、非 `not_yet_effective`）；
  2. 位于事实区（非 `not_fact_zone`）；
  3. 状态为 `active`（非 `retracted`、非 `disputed`）；
  4. 已绑定证据（非 `no_evidence`）；
  5. 当日不存在未裁决的冲突（非 `conflict`）。

任一条件不满足时，该事实不得作为确定依据，并记录对应的原因代码（`expired`、`not_yet_effective`、`not_fact_zone`、`retracted`、`disputed`、`no_evidence`、`conflict`）。

### 1.4 冲突检测（只陈列，不自动裁决）

冲突定义为：事实区中两条未撤回（`status != retracted`）、不同 `fact_id` 的记录满足：

1. `entity_id` 相同；
2. 属性相同（属性名折叠后相同，或一方属性名命中另一方的 `aliases`）；
3. 适用条件归一后完全相同（如 CLTC 与 WLTC 条件不同，不构成冲突）；
4. 有效期存在交集（存在至少一天两者同时是各自 `fact_id` 的当日有效版本；给出 `--as-of` 时只看该日）；
5. 归一后的值不完全相同（`21.98 万元` 与 `219800 元` 相同；`620 km` 与 `600~650 km` 不同）。

同一 `fact_id` 的不同版本属于“更新”，不计为冲突。工具**绝不自动裁决**冲突，只输出冲突清单并使冲突中的事实当日不可作为确定依据，须由人工核对后撤回或更正。

## 2. 归一规则（`normalize`）

所有文本匹配与比较先经过文本折叠：Unicode NFKC 规范化、字母转小写、连字符变体（`‐`/`‑`/`‒`/`–`/`—`/`−` 等）统一为 `-`、波浪号（`～`/`〜`）统一为 `~`、连续空白折叠为单个空格。紧凑模式（`compact`）进一步去除空白与连字符，用于型号、属性词和实体名匹配。

### 2.1 数值与中文数字

- **阿拉伯数字**：支持整数、小数和规范千分位逗号（如 `219,800`、`1,850.5`）。不合法的千分位分组退回普通数字解析。
- **中文数字**：
  - 支持 `零 〇 一 二 两 三 四 五 六 七 八 九`、`十 百 千 万 亿`（含繁体 `萬 億`）及大写 `壹 贰 叁 肆 伍 陆 柒 捌 玖 拾 佰 仟`；
  - 纯数字无单位字时按位读（如“二〇二六” = `2026`）；但两位纯数字（如“三四年”“七八成”）不按位读，避免误判约数口语；
  - “点”表示小数点，支持小数后接“万 / 亿”（如“二十一点九八万” = `219800`）；
  - 口语省略：“两万五” = `25000`、“三千五” = `3500`、“一百五” = `150`；带“零”时不省略（“一百零五” = `105`）；
  - 单个中文数字仅在带数量级词，或搭配时长/年月量纲（如“五年”“三天”）时才识别为数量，避免将“一度”“一个”误识为数值。
- **前缀百分比与货币符号**：支持 `百分之 X`（归一为 `X %`）和前置 `¥`（无后缀单位时补为 `元`）。
- **变化量排除**：数值前紧接“提升、提高、增加、增长、增幅、上涨、上调、下降、降低、减少、下调、降幅、降价、直降、立减、优惠、便宜、补贴、缩短、延长、高出、多出、低出、相差、差距、涨幅、涨、降、多、少、贵、快、慢”等变化量词（排除“最多、至多、差不多、至少、最少、不少、许多、很多”）时，标记为 `delta`，不作为属性值拆解。
- **非数量排除**：序数（前有“第”，如“第 3 名”）、紧贴字母/数字/小数点之后（如“K5”“v2.0”）、以及后跟未收录单位（如“3 档”“5G”）不识别为数量。

### 2.2 范围、约数容差与上下界

数值统一表示为取值区间 `Interval(low, high, low_closed, high_closed)`：

| 写法 | 语义与区间 | 示例 |
|---|---|---|
| 无限定词 | 精确点值 `[X, X]`，**不加任何容差** | `620 km` → `[620, 620]` |
| `约 / 大约 / 约为 / 约合 / 大概 / 大致 / 差不多 / ~ / ≈ X` 或 `X 左右 / 上下` | `[X - t, X + t]`，其中 `t = max(末位有效数字所在位 / 2, |X| × 2%)` | 约 620 → `[607.6, 632.4]`；约 600 → `[550, 650]`；约 22 万 → `[21.5 万, 22.5 万]` |
| `X 多 / X 余`（可在数量级或单位前后） | `[X, X + 末位有效数字所在位)` | 600 多 → `[600, 700)`；20 多万 → `[20 万, 30 万)` |
| `近 / 将近 / 接近 / 逼近 X` | `[0.9X, X]`（排除“最近 / 附近 / 靠近”等） | 近 20 万 → `[18 万, 20 万]` |
| `超过 / 高于 / 大于 / 多于 / 突破 / 逾 / 超 X` | `(X, +∞)` | 超过 600 → `(600, +∞)` |
| `X 以上` 或 `至少 / 最少 / 不低于 / 不少于 / 起码 X` | `[X, +∞)` | 600 以上 → `[600, +∞)` |
| `不到 / 不足 / 低于 / 小于 / 少于 / 未满 X` | `(-∞, X)` | 不到 6 秒 → `(-∞, 6)` |
| `X 以内 / 以下` 或 `最多 / 至多 / 不超过 / 不高于 / 最高不超过 X` | `(-∞, X]` | 6 秒以内 → `(-∞, 6]` |
| `A～B` / `A-B` / `A—B` / `A 至 B` / `A 到 B` | 闭区间 `[A, B]`；前数省略数量级时共享后数数量级（如 `20-25 万`） | `600～650 km` → `[600, 650]` |

**区间比较规则**（`compare_values`）：

- 事实是点值：陈述区间包含该点 → 一致（`MATCH`）；否则不一致（`MISMATCH`）。
- 陈述是点值、事实是区间：事实区间包含该点 → `MATCH`；否则 `MISMATCH`。
- 两者都是区间：一方完全包含另一方 → `MATCH`；两者无交集 → `MISMATCH`；仅部分重叠 → 不可比（`INCOMPARABLE`）。

### 2.3 单位换算与组合数量

内置单位表按量纲定义换算到基准单位的精确 `Decimal` 系数：

- **长度**（基准 `m`）：`mm`、`cm`、`m`、`km`（公里、千米）、`英里`（mile/miles）、`英寸`（inch/吋）
- **货币**（基准 `元`）：`元`（块、块钱、元人民币、rmb、cny）、`千元`、`万元`（万块）、`亿元`
- **电量**（基准 `kWh`）：`kWh`（千瓦时、度、度电、kw·h、kw.h）、`Wh`（瓦时）
- **功率**（基准 `kW`）：`kW`（千瓦）、`W`（瓦）；**马力**（`马力`、匹、ps）独立量纲
- **扭矩**：`N·m`（nm、n.m、牛米、牛·米）
- **速度**：`km/h`（公里/小时、千米/小时、公里每小时、千米每小时、kph）
- **时长**（基准 `s`）：`ms`、`s`（秒、秒钟、sec）、`min`（分钟）、`h`（小时、个小时、hr）、`天`
- **年月**（基准 `个月`）：`个月`、`年`（1 年 = 12 个月，不与“天”互换）
- **百分比**：`%`（percent）
- **质量**（基准 `kg`）：`mg`、`g`、`kg`（千克、公斤）、`吨`（1000 kg）、`斤`（0.5 kg）
- **容积**（基准 `L`）：`mL`（毫升）、`L`（升）
- **电压**（基准 `V`）：`V`（伏、伏特）、`kV`（千伏）
- **温度**：`℃`（°c、摄氏度）
- **计数单位**：`座`、`个`、`辆`、`台`、`人`、`次`、`家`、`项`（各自独立，互不换算）

规则：

- 同量纲自动换算至基准单位比较（如 `219800 元` 与 `21.98 万元` 一致，`1.85 吨` 与 `1850 kg` 一致）；
- 量纲不同 → 不可比（`INCOMPARABLE`）；
- 未收录的单位自成量纲，只能与字面折叠后相同的单位比较；
- 陈述未写单位而事实有单位时，按事实单位理解；若陈述带“万 / 亿”等数量级词（如“21.98 万”），同时尝试按该量纲基准单位（元）比较，任一一致则判一致；
- **组合数量**（如“5 年或 15 万公里”）：拆成多个 `Measure`，按量纲逐项比较；任一量纲不一致 → `MISMATCH`，否则至少一项一致 → `MATCH`，均无可比量纲 → `INCOMPARABLE`。

### 2.4 日期精度

识别 `YYYY年M月D日/号`（含中文数字如“二〇二六年三月十八日”）、`YYYY年M月`、`YYYY-MM-DD` / `YYYY/M/D` / `YYYY.M.D`、`YYYY-MM`、`YYYY年`（排除“2026 年款 / 年代 / 年前”等），保留年（`year`）、月（`month`）、日（`day`）三级精度（合法年份 1900～2199）。

两个日期按**较粗的精度**比较：`2026 年 3 月` 或 `2026 年` 与 `2026-03-18` 一致，`2026 年 4 月` 与 `2026-03-18` 不一致。

### 2.5 型号与年款

- **型号键**（`model_key`）：对型号名做紧凑折叠（NFKC、小写、去空白与连字符），使 `S7`、`Ｓ７`、`s 7`、`S-7`、`ＬＸ－Ｍ２２０` 与 `LX-M220` 归一为同一个键。
- **年款拆解**：从型号文本中拆出 `YYYY 年款` / `YYYY 款` 的四位年份。在陈述拆解中，年款仅在事实库本身按 `model_year` 区分事实时写入 `conditions`，否则保留在 `ext.model_year`。

### 2.6 适用条件

条件键转小写并去首尾空白，条件值按规则归一：

- `test_cycle`：`CLTC` / `CLTC-P` → `CLTC`；`WLTC` / `WLTP` → `WLTC`；`NEDC` → `NEDC`；`EPA` → `EPA`。四套测试工况互不可换。
- `trim`：折叠后去掉末尾的 `版本 / 版 / 款 / 型` 后缀（“长续航版”与“长续航款”归一为同一值）。
- `model_year`：提取数字，两位年份自动补前缀 `20`（“26 款” → `2026`）。
- `soc_range`：提取两个百分数归一为 `A%-B%`（如 `30% 充到 80%` → `30%-80%`）。
- 其他条件键：按紧凑折叠后的字面比较。

**条件可比规则**：陈述写明的**每一个**条件，事实都必须具有同名且归一后同值的条件，两者才可比；事实多出的条件（如事实标有 `trim=长续航版` 而陈述未提及版本）视为陈述未限定，不影响可比。

## 3. 陈述拆解规则与边界（`claims`）

默认拆解器为纯规则实现（`rules`），离线可用；模型拆解仅保留插件注册接口，本仓库不提供模型实现，默认不启用、不联网。

### 3.1 处理顺序

在折叠文本上依次扫描并最终映射回原文的 Unicode 码点位置 `[start, end)`（满足 `原文[start:end] == claim.text`）：

1. **噪声遮蔽**：遮蔽引用角标（`[1]`、`[^2]`、`【3】`、`〔4〕`）、行首列表序号（`1.`、`2、`、`3)`）及 Unicode 上标数字。
2. **实体识别**：匹配事实库实体名与别名，跨实体最长优先；英文字母/数字实体两侧不得紧贴其他字母数字；落在 `exclusions` 排除词内不算（如“波澜序曲”不匹配“澜序”）。品牌紧跟车型时：车型隶属该品牌则合并为该车型；车型属于其他品牌（如“朔风 S7”）或紧跟未登记型号代码（如“澜序 S9”）则记为未知实体，不误归属。
3. **条件识别**：识别测试工况、四位年款、版本配置、事实库已登记的其他条件值，以及（当事实库含 `soc_range` 时）电量区间。
4. **日期、属性词、数量与型号码识别**：属性词来自事实库属性名、别名及内置常见同义表；变化量不拆；型号码需长度 ≥ 3 且符合字母数字组合特征。
5. **分句与小句切分**：按 `。!?;\n` 分句，按 `，、|`（以及非千分位的 `,`）分小句；识别 Markdown 表格的表头属性与条件。
6. **值与属性配对**：优先同一小句内最近的前置属性词，其次后置属性词（如“2026 年 3 月上市”），其次表格表头同列属性；若小句在值之前仅含实体、条件与虚词（如“岑野 K5 为 580 公里”），沿用同一句前一小句的属性。值与属性的类型或量纲不兼容时不拆（如“电池 8 年质保”不会误拆为电池容量）。
7. **实体与条件归属**：优先同一小句值前最近实体，其次值后实体，再次前文最近提及的车型（处理“它的……”“该车……”“这款车……”及主语省略；前文最近为未知实体时不归属）。含“分别”的并列句按顺序一一对应。条件先在小句内按唯一/最近分配，再继承表头与同句前导条件小句（如“在 WLTC 工况下，……”）。
8. **不拆的句式**：
   - 问句（以 `?` 结尾、小句以 `吗/么` 结尾，或含 `是否 / 是不是 / 有没有 / 能不能 / 会不会`）；
   - 否定陈述（值前出现 `不是 / 并非 / 不为 / 没有 / 并无 / 未达 / 达不到 / 不会 / 不可能 / 不止 / 绝非`；注意“不低于、不超过”是上下界，不是否定）；
   - 假设与传闻（句首到值之间出现 `如果 / 假如 / 假设 / 倘若 / 要是 / 若是 / 传闻 / 网传 / 据传 / 谣传 / 据说 / 有传言 / 有人说`）；
   - 裸数字（无单位且无数量级词）若与属性词之间已隔着另一个值，不配对。

### 3.2 已知拆不出的写法

规则拆解器明确覆盖**数值、型号、日期**三类结构化陈述，以下写法在当前规则实现下可能拆不出或留为不可核验：

- **自由文本定性描述**：如“静谧性出色”“空间宽敞”等不含结构化数值/型号/日期的表述；
- **未登记的属性说法**：回答使用的属性名既不在事实库属性名/别名中，也不在内置常见同义表中；
- **复杂跨句或隐含指代**：多实体交替出现后的远距离代词指代、未命名产品直接报数字、或需要常识推理才能还原主语的句子；
- **非标准排版与复杂表格**：跨行/跨列合并单元格、无分隔线的纯空格对齐表格；
- **未收录单位且与事实库写法不一致**：如非标准口语量词；
- **隐含计算关系**：如“续航比老款多了 10%”这类仅给相对变化量的句子（变化量按设计标记为 `delta` 跳过）。

## 4. 双向判定、两个分母与两个口径（`judge`）

### 4.1 两个方向、两个分母（严禁混用）

| 方向（`direction`） | 遍历对象（分母来源） | 判定标签 | 产出指标 |
|---|---|---|---|
| **回答 → 事实库**（`answer_to_facts`） | 有效观测中拆出的每一条陈述 | `supported` / `contradicted` / `unverifiable` | 回答准确率、不可核验率 |
| **事实库 → 回答**（`facts_to_answer`） | 封存题库按题配置（`core_fact_ids`）且查询日可用的核心事实 | `present_correct` / `present_wrong` / `missing` | 核心信息呈现率 |

- 只处理 `status = "valid"` 且 `answer_text` 非空的观测；无效观测计数跳过，不进入任何分母。
- `unverifiable` **既不等于“缺失”，也不等于“错误”**。
- 未配置 `core_fact_ids` 的题目不进入呈现率分母；配置了但在查询日不可用（如过期、撤回、无证据、冲突）的核心事实自动排除出分母，并在摘要 `excluded_core_facts` 中逐条说明原因。

### 4.2 回答 → 事实库（`answer_to_facts`）判定步骤

对每条陈述按以下顺序判定：

1. 若 `claim_type == "free_text"` → `unverifiable`（`free_text`，注明“自由文本判定未验证”）。
2. 若缺少实体、缺少属性、事实库中无同实体同属性概念的事实、或陈述值无法归一 → `unverifiable`（`no_entity` / `no_attribute` / `no_fact` / `value_unparsed`）。
3. **条件过滤**：检查陈述条件与各候选事实条件是否可比。
   - 若没有任何条件可比的事实（例如陈述写 NEDC 而事实库只有 CLTC/WLTC）→ `unverifiable`（`condition_differs`）。**条件不同绝不判为矛盾。**
   - 若陈述未写条件，则该属性所有条件版本的事实均参与可比；与任一可用事实一致判 `supported`，与所有可用事实都不一致判 `contradicted` 并在理由中列出全部比对对象。
4. **可用性过滤**：若所有条件可比的事实在查询日均不可作为确定依据 → `unverifiable`（`fact_unusable`），理由列出不可用原因。
5. **值比较**：逐一比较陈述值与各可用事实的值：
   - 与任一可用事实一致 → `supported`（`match`）。
   - 全部为不可比（如量纲不同、范围部分重叠）→ `unverifiable`（`incomparable`）。
   - 存在不一致时：
     - **过期/旧版本检查**：若陈述值与该事实（或同类已整段过期事实）在查询日已过期或已被更正的旧版本一致 → **`contradicted`（`stale_match`），并在理由中明确注明“与已过期的版本一致（过期信息）”或“与已被更正的旧版本一致”**，同时给出当前有效版本的值；
     - 若陈述值与另一条不可用（且非单纯过期，如无证据或有冲突）的可比事实一致 → `unverifiable`（`matches_unusable`），不下矛盾结论；
     - 其余情况 → `contradicted`（`mismatch`）。

### 4.3 事实库 → 回答（`facts_to_answer`）判定步骤

对每条查询日可用的核心事实，在对应观测拆出的陈述中筛选同实体、同属性概念、条件可比的非自由文本陈述：

- 至少有一条与核心事实值一致 → `present_correct`；
- 否则，若存在与核心事实值不一致的陈述，且该陈述并非与同实体同属性的另一条有效事实一致（例如回答说的是 WLTC 540 km，不算 CLTC 620 km 呈现错误）→ `present_wrong`；
- 否则 → `missing`。

### 4.4 准确率的两个口径与事前登记

`judge` 同时输出两个口径的准确率以及不可核验率：

- **可核验口径**（`accuracy_verifiable`）= `支持 / (支持 + 矛盾)`
- **严格口径**（`accuracy_strict`）= `支持 / 全部陈述`
- **不可核验率**（`unverifiable_rate`）= `不可核验 / 全部陈述`
- **核心信息呈现率**（`presence_rate`）= `呈现正确 / 应呈现核心事实总数`

分母为 0 时一律返回 `null` 并附 `null_reasons` / `null_reason`，不返回 `0` 或 `1`。

**验收使用可核验口径还是严格口径，必须在项目封存前预先登记，严禁看到核验结果后再挑选更有利的口径。**

## 5. 判定校准与“判定精度不足”（`calibrate`）

自动判定器（无论是规则还是模型）自身可能出错。`geo-facts calibrate` 将判定器输出与人工金标按 `id` 对齐评估：

- 仅在一边出现的 `id` 单独计数并报告，不参与计算；同一文件内 `id` 重复直接报输入错误（退出 2）。
- 判定器给出金标中不存在的标签时，照常计入混淆矩阵并记为错误，且在报告中单独提示。
- 输出混淆矩阵（行为金标、列为判定器）、各标签的精确率、召回率、F1，以及整体准确率与错误率。
- 准确率、错误率及各类精确率、召回率均附 **Wilson 双侧置信区间**（默认置信水平 `0.95`，标准正态分位数）；F1 不是二项比例，只给点估计。

### “判定精度不足”的统计含义

设目标准确率为 $T$（默认 $0.98$），允许的错误率预算为 $1 - T$（默认 $0.02$）。设对齐样本上判定器错误率的 Wilson 双侧区间上限为 $U$：

- 当 **$U > 1 - T$** 时，输出固定结论 `insufficient_precision`（“**判定精度不足，无法证明达标**”），退出码 **`3`**。原因在于：在给定置信水平下，判定器自身可能产生的误差已经超过验收所需的误差预算，因此**禁止**依据该判定器的结果给出“已达 98%”之类的肯定结论。
- 当 **$U \le 1 - T$** 时，输出 `adequate`（退出码 `0`），但措辞仍仅陈述“在本金标集上，判定器错误率的区间上限不超过 $1 - T$”；该结论只针对该批金标与当前版本判定器，金标集是否具有业务代表性仍须人工确认。

## 6. 合成标注集与质量门槛（`benchmarks/`）

为验证规则实现本身的正确性，仓库在 `benchmarks/` 提供现场生成的合成标注集与基准脚本：

- **独立生成、隔离评测**：`benchmarks/generate.py` 与 `benchmarks/run_benchmark.py` 不 `import geo_facts` 的任何实现逻辑；基准只通过 CLI 子进程驱动 `init → import → judge / gate`。
- **开发集与保留集分离**：`dev`（默认 seed `20261008`）与 `holdout`（默认 seed `90417`）使用不同 seed、不同车型与属性组合、不同句式模板及不同注入攻击变体。调参只用开发集；保留集仅在里程碑验收时运行并记录。
- **规模要求**：每个 split 至少包含 300 条金标（其中至少 100 条难例，涵盖单位换算、约数、范围、中文数字、千分位、全半角大小写、条件不同、过期版本、竞品同名、日期精度、实体省略、多陈述句与容差边界），以及注入类至少 40 条攻击样本与 60 条正常样本。
- **数值、型号、日期类的门槛**：
  - 矛盾检出召回率 ≥ `0.95`
  - 矛盾判定精确率 ≥ `0.95`
  - 条件不同被误判为矛盾的比例 ≤ `0.02`
  - 注入类攻击样本检出率 = `1.00`（全部检出 `G-HIDDEN-TEXT` 或 `G-PROMPT-INJECTION`），正常样本误拦率 ≤ `0.02`

### 局限性声明

1. **合成标注集结果只能说明实现符合预期，不代表真实业务准确率。** 真实平台回答的语言风格、长尾句式与歧义远比合成模板复杂。
2. **自由文本判定在获得真实人工金标（建议 ≥ 300 条、双人标注）并完成校准前，一律标为“未验证”。**
3. 事实库的准确性取决于人工维护与证据核验；工具只负责按规则比对与留痕，无法代替人工判断信源真伪。
